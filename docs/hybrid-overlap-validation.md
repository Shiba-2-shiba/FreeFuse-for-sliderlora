## 配布ファイルと開始手順

最初にA/B/CのUIを開き、モデル・style・Sliderのファイル名を環境に合わせる。デフォルトは女性手前・強い重なり、seed 42、余白4。参照構図を確認してからD用maskを作成し、D側のREQUIREDプレースホルダーを実ファイルへ変更する。DとA/B/Cでモデル・prompt・seed・強度・画像サイズ・試行設定を揃える。

次のコマンドでケース・seed・余白の別条件を作れる。出力先は条件ごとに分ける。

```bash
python tools/build_hybrid_validation_workflows.py \
  --case woman_front_strong_overlap --seed 444444 --radius 4 \
  --output-dir generated/woman_front_s444444_r4
```

caseは `original`、`man_front`、`park`、`woman_front_strong_overlap`。余白は0/2/4。過去の公園条件は `--case park --seed 444444`、室内と男性手前はseed 42を指定する。Dの入力は `--support-mask` と `--protected-mask` で指定でき、`--input-dir` にComfyUIのinputフォルダを指定すると必要ファイルの存在・二値形式・サイズを検査する。これらのパスは、その実行環境にあるファイルを指す必要がある。生成コマンドは出力先の所定5つのJSONを置き換えるため、編集済みのworkflowがある場合は必ず別の出力フォルダを使う。

## 目的と判定順序

対象女性の顔だけでなく身長・胴脚・頭身が一貫して変わり、男性の顔・身長・主要な体格を維持することを優先する。接触を自然にするための手・腕の小さな位置調整は許容するが、顔片の増殖、肩・腕の融合は許容しない。

既存結果では、非接触の室内はA、非接触の公園はCが相対的に良好で、男性手前の接触は全方式に破綻が残った。今回の順序は、良い静的マスクでも破綻するかを調べ、その後に自動抽出や動的追跡の改良方針を決めるもの。ON収集やhybridが常に優れるという前提は置かない。

## 追加する構図

女性が前、男性が後ろに立ち、女性の輪郭が男性の胴体を大きく隠す構図を追加する。男性は少し横へずらし、顔を確認できるようにする。両者とも全身・足元を含め、服を着た立像とする。seed 42を主条件、444444を再現性確認に使う。

プロンプトの指定だけで構図成立とはしない。まずOFF参照画像を目視し、以下を満たす場合だけ「女性手前・強い重なり」として評価する。

- 女性が手前、男性が後方という前後関係を輪郭で確認できる。
- 男性の胴体の一部が女性に相当程度隠れる。単なる肩同士の接触や横並びではない。
- 男性の顔を評価でき、両者の足元・全身比率を確認できる。
- 余分な人物や元からの重大な人体破綻がない。

不成立なら `composition_not_met` と記録する。都合の良い出力だけを成功例として数えない。別seedを追加する場合は失敗seedも残し、同じケースのA/B/C/Dでpromptとseedを揃える。前後に遮蔽された人物の「可視マスクの積」が大きいことを構図成立の基準にしてはいけない。正しい可視領域は互いに排他的になるためである。

## 比較する条件

| 条件 | 対象マスク | 保護マスク | 目的 |
|---|---|---|---|
| A | OFF収集 | OFF収集 | 既存基準 |
| B | ON収集 | ON収集 | 従来の単純ON対照 |
| C | ON対象からOFF保護を除く | OFF収集 | hybrid基準 |
| D | 人手で補正した編集範囲から同じOFF保護を除く | 同じOFF収集 | 自動抽出と生成方式の切り分け |

A/Cはすでに保護元が共通。既存結果を使う場合は、実行設定・モデル・prompt・seed・初期入力と元のマスクファイルが対応することを確認する。今回の集計JSONと比較画像だけでは完全な再実行入力を復元できない。

初回はstrength 4、8 steps、CFG 1、収集step 2/block 18、top_k 0.2、temperature 10000、穴埋め0・参照膨張0、最終選択余白4を固定する。収集Sampler自身はstrength 0、ON収集側の上流Slider Loaderだけがstrength 4。本生成MODELは元のstyle付きbase、LATENTは元の空latentとし、ONモデルや収集後latentを流用しない。

## D用マスクの作り方

Dの手動入力は未作成のプレースホルダーで、画像に合わせた人手の判断が必要。自動で正解マスクを作成済みとは扱わない。

1. 同じケース・seedのOFF参照と、保存したOFF保護マスクを用意する。
2. 対象の旧シルエット、変形後に必要な範囲、旧人物が消えて再構成される空間を考えて編集用の白黒マスクを作る。白が編集対象、黒が対象外。
3. 背景の木や壁への飛び地を除き、頭だけでなく胴・腰・脚が必要な範囲で連続して扱われるか確認する。
4. 男性の実際の顔・主な胴体を侵さない。手・腕周囲を変更する場合は範囲と理由を記録する。男女を同面積に揃えない。
5. RGBの場合は3チャンネルを同じ白黒値にする。LoadImageMaskはredチャンネルを使用し、alphaの反転に依存しない。マスクは同じcanvasサイズで用意し、blurやJPEG圧縮を使わない。保存したOFF保護がtoken-gridサイズなら、手動supportも同じサイズの二値PNGにする。画像サイズのsupportと小さいgridの保護をそのまま組み合わせると既存Samplerが拒否する。ツールは無断でリサイズしない。

重要：手動マスクから男性を除くだけでは、最終余白4の拡張でその場所へ戻る可能性がある。OFF保護の取りこぼしがある場所は特に注意する。必ず膨張後の実効マスクを検査する。

手動の男性除外領域が必要になった場合は、同じ除外を比較する全条件へ適用する別実験にする。Dだけ保護条件を変えた結果を自動抽出の効果と解釈しない。膨張後に共通の除外を差し引いた最終マスクを再生するなら、再生側の余白を0にして再膨張を防ぐ。

## 保存とオフライン検査

MaskPreviewのslot 7（0始まり）が実際の予測選択、slot 8が選択余白。raw targetやreference targetの画像と混同しない。新workflowは本生成の各条件について、この2種類を明示的にPNG保存する。

検査ツール `tools/audit_mask_support.py` は次の3ファイルを位置引数として受け取る。

```bash
python tools/audit_mask_support.py D_reference_target_before_dilation.png \
  D_reference_protected.png D_effective_prediction_mask.png \
  --anatomical-exclusion male_exclusion.png \
  --compare-effective reference_effective.png \
  --output support_audit.json
```

後半の3オプションは任意。例のファイル名には、実際の保存prefixや連番を含む名前を指定する。A/B/C/Dそれぞれの `reference_target_before_dilation`、`reference_protected`、`effective_prediction_mask` の3出力を使う。Dのtargetには、人手で描いた減算前supportや、入力canvas上の `D_support_minus_P_off` ではなく、Samplerのgridへ変換した後の `D_reference_target_before_dilation` を指定する。`--output` は既存ファイルを上書きしない。対象・保護・実効maskは同じgridサイズの二値PNGを使う。目視用の半透明overlayや画像サイズへ補間したカラー比較図は入力にしない。

この検査では、対象と保護の重複、実効選択への対象の欠落、実効選択と保護・任意の男性除外との重複、追加余白、8近傍の連結成分などを調べる。連結成分の座標と大きさは算出するが、そこが木・顔・身体かは自動判定しない。raw similarity tensorの検証や人物保持・画質の保証を行うツールではない。

現行処理は最大の対象連結成分だけを背景側へ拡張し、他の成分は維持する。顔・胴・脚が分断されていると、全てに同じ余白が付くとは限らない。最大成分が背景であるかは、実効マスクと成分座標を確認して判断する。

## 評価記録

| 項目 | 記録すること |
|---|---|
| 構図成立 | 女性手前、男性後方、強い遮蔽、顔と足元の可視性。未成立は別集計 |
| 対象の変化 | 顔、身長、胴脚、頭身を別々に記録 |
| 旧領域 | 旧顔・肩・襟・服・脚の残存、重複像 |
| 男性の保持 | 顔、身長、主な体格をOFF参照と比較。画素不変とは区別 |
| 接触 | 手・腕の小移動か、融合・欠損・余分な肢なのか |
| 境界 | 首と胴、腰と脚、人物間、背景補完の連続性 |
| マスク | raw/実効の取り違え、保護侵入、人物内の欠落、背景への飛び地 |
| 監査 | 保存した各runの診断検証とオフラインmask検査の結果 |

全体適用ON参照では男性も変形する。対象の変化方向の参考にはなるが、「成人男性との正しい相対サイズ」の正解画像としては使わない。また、step 2のmaskを完成参照へ重ねた図だけでは、収集時の人物取り違えと後の形状移動を区別できない。

## 次の判断

- Dで全身体型と旧領域が改善：自動抽出・人物への割当・編集範囲の不足を優先して改良する。
- 適切な最終選択を確認したDでも破綻：固定した領域での予測混合、旧領域の再構成、途中の形状変化を検討する。1枚の手動maskの失敗だけで原理的に不可能とはしない。
- 非接触は改善し強い重なりだけ失敗：遮蔽順序と接触境界の扱いを優先する。
- その後、有望な同一target/protectedを固定して選択余白0/2/4を比較する。余白と収集源を同時に変えない。

同一latentでのOFF/ON観測や動的マスクは後続候補で、今回の実装には含めない。

## コスト・検証限界

キャッシュなしのA/B/C全体は68 NFE。既存マスクを読み込むD単独は16 NFE。Dの余白0/2/4を全て生成すると48 NFEで、同条件の余白4が既にあれば追加は32 NFE。時間・VRAMの保証ではない。不要な保存枝を残すと、その祖先の収集が実行される点に注意する。

こちらでは新workflowの構造・ツールのCPUテストを行う。ComfyUIでのUI再読込、モデルを使った生成、INT8動作、画質・人体の改善は別途実機で確認する。既存の比較CLIが要求する同一partition条件は緩めていない。異なるmaskの画質比較をそのまま既存CLIで同条件比較として扱わない。
